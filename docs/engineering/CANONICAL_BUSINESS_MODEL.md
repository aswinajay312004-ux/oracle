# Canonical business model

The order model is the contract between reading (Excel) and writing (Oracle). It is a JSON document per order inside
a draft (`draft.orders[i]`), created by `workbooks.base_order()` and kept server-side by `local_store.edited_orders`
(people can change business values; provenance and source snapshots stay server-owned).

## 1. Order

| Field | Meaning | Source states |
|---|---|---|
| `id` | POPPYS identity of the order inside the draft (not a business key) | generated |
| `sheet` | worksheet the order was read from | reader |
| `buyer`, `style`, `description`, `po_number`, `order_ref`, `order_date`, `ship_date`, `season`, `merch`, `sample_type`, `exporter`, `against`, `department`, `gender`, `packing_type`, `components` | business header (keys of `backend/fields.py`) | file / person / company default |
| `qty_unit` (`PCS` / `PACK` / empty = not decided), `pieces_per_unit` | unit of the size quantities | file / person / same buyer's saved layout |
| `quantity_basis` (`sample` / `order_demo` / `unconfirmed`) | which quantities of the file are saved | person / saved layout |
| `lines[]` | the quantities that will be saved: `{id, label, color, declared_total, original_total, provenance, sizes[]}` | file / person |
| `lines[].sizes[]` | `{id, size, quantity, source, size_source, blank?}` | file / person |
| `order_lines[]`, `sample_lines[]` | the file's own order and sample sections, kept unchanged for comparison | file |
| `fabrics[]` (+ `yarns[]`), `accessories[]` | BOM rows with their source cells | file / person |
| `packs`, `workbook_pieces` | the file's pack header (packs × pieces) and its total pieces | file |
| `provenance{field: {...}}` | where each header value came from: `{sheet, cell, value, formula}`, or `{derivation}` for defaults and calculations, plus `question` when the value is doubtful | reader / server |
| `warnings[]` | notes from reading the file | reader |

## 2. Lineage

Every value can answer "where did this come from?":

| Kind | Marked by |
|---|---|
| Read from a cell | `{sheet, cell, value, formula}` (the value as it was in the file, even after a person edits the field) |
| Typed by a person | no cell; the audit log has the change (`edit` event with old → new); size rows typed in have `source.origin = "Manual correction"` |
| Company default | `{derivation: "Company default (Settings)"}` |
| Saved layout decision | `{derivation: "Confirmed for the saved layout …", reason: "template", template}` |
| Calculated | planner `derived[path]` with the formula text (fabric kg, accessory scaling) |
| Generated by Oracle | `ORDMASID` etc. come from `PP_RECORD_SEQ` at commit; never shown as business identifiers |

## 3. Entities not in the model yet (spec §4.1)

| Entity | Status |
|---|---|
| Delivery schedule (several ship dates / quantities) | Not implemented |
| Price, currency, commercial terms | Not implemented (not read, visible as "not read" when numeric) |
| Company order reference distinct from buyer PO | `order_ref` vs `po_number` — Implemented |
| Versioned schema of the model (`model_version`) | Not implemented — Known risk: changes to the model rely on additive keys |
| Other document types (quotation, invoice) | Not implemented, out of scope for this release |
