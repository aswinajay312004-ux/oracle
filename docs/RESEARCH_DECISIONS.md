# POPPYS AI: Engineering Decision Record (Excel/JSON → Axpert/Oracle)

Scope: Excel-family and JSON uploads only. No PDF, OCR or CAD. Offline and on-prem: no cloud AI APIs; Ollama is optional and runs locally. This record is built from six verified research topics: formats, matching, production, oracle, ux and erp_data. The `oracle`, `ux` and `erp_data` research was cut off in the computed task, so it was read in full from this workflow run's journal. Every verifier correction has been applied and every refuted claim dropped. The list of those changes is at the end of §2. Some statements describe the current code; they were checked against `/home/user/oracle` at commit `c939d85`.

---

## 1. Executive summary

- **Readers.** Every format is read into one cell model: value, type, fmt, displayed text, merges, hidden rows/columns/sheets, plus per-sheet capability flags. openpyxl and xlrd stay the primary readers because they are the only ones that expose merges, hidden state and number formats. python-calamine reads .xlsb and .ods and is the fallback for damaged or Strict OOXML files; its results are flagged `reduced_fidelity`. The format is decided by sniffing the content; the file extension is only a tie-breaker. Every parse runs in a spawned worker with a memory cap and a time limit. Before calamine sees a ZIP-based file, decompression is checked against the declared sizes, because the zip 8.6 crate inside calamine does not enforce them.
- **Matching.** Column matching is a deterministic pipeline and every score comes with its evidence. It runs in this order: region detection, header-band scoring, reshape operators, name and instance signals, COMA DIR_BOTH selection, a 1:1 Hungarian assignment, validators with a repair loop, and confidence bands. The only new runtime dependency is RapidFuzz (MIT). Auto-apply is all-or-nothing: every required field must be in the AUTO band. qwen2.5:7b only proposes: its vote adds at most +0.10, it can never lift a column into AUTO, and it never writes SQL.
- **Data integrity.**
  - **Model and units.** One canonical Pydantic order model for both Excel and JSON. Quantities are stored in pieces, using a unit dictionary based on UN/ECE Rec 20/21.
  - **Masters and checks.** Master data is never created implicitly. Control totals are compared at three points: extraction, the approved payload, and the Oracle read-back.
  - **Approval and posting.** Maker-checker approval is bound to a SHA-256 of the payload. Posting is one Oracle transaction that re-checks for duplicates inside the transaction and reads the rows back before and after commit.
  - **Open blocker.** A direct INSERT bypasses Axpert's Gen/MD maps, its numbering and its standard columns. Agile Labs must confirm this is acceptable before production posting.
- **Oracle and NL questions.**
  - **Driver and accounts.** Pin `oracledb==4.0.2`: issue #610 makes 26.0.x Thin pools hang. Use two fixed-size pools and two accounts: POPPYS_RO with READ grants only, and POPPYS_WR with INSERT on the six order tables only.
  - **Query limits.** Every query is bounded by call_timeout, a wall-clock budget and FETCH FIRST.
  - **Large-database techniques.** Row counts come from statistics first. Lists use keyset paging. Fuzzy text is resolved through a local FTS5 value index so Oracle only receives exact, typed binds.
  - **NL questions.** A question is mapped to a catalog intent and compiled into an allow-listed SELECT template. The golden question set gate is ≥95%.
- **Production.**
  - **Security.** Map the app to OWASP ASVS 5.0 L2 and fix the gaps found in `backend/main.py`: cookie flags, CSRF, the in-memory per-IP throttle, PBKDF2 at 300k iterations, `str(exc)` leaking into error responses, the CSP, and a body limit that only reads Content-Length.
  - **Operations.** JSON logs with request IDs; /healthz and /readyz; a WinSW service; an embeddable CPython zip built from a hashed wheelhouse; SBOM, pip-audit and licence gates; nightly verified SQLite backups with a restore drill.
  - **Oracle Free.** It is capped at 12 GB, 2 GB RAM and 2 CPU threads, so it is a rehearsal and CI target only.

**Verifier corrections applied (refuted or changed claims):**
- **Cookies:** `__Host-` cookies do not work on http://localhost in Chromium (refuted). Unprefixed Secure is used, or TLS.
- **ZIP pre-check:** reading members through CPython `zipfile` is not a valid pre-check for calamine (CRC-of-prefix trick). Raw-zlib measurement or rewriting the archive is required.
- **oracledb:** stay on 4.0.2, not 26.0.1 (issue #610). `pool_alias` is the pool label; `pool_name` is DRCP. A READ ONLY transaction still allows LOCK TABLE; READ grants block it. EXPLAIN PLAN conflicts with read-only sessions. On 23ai, ORA-28194 comes from read-only users, and the feature is for PDB-local users only. Transaction Guard is supported in Thin mode.
- **Licences:** the DIN-SQL repo is MIT (claim of no licence refuted); its code is still not copied, for technical reasons.
- **Frontend:** there are no inline styles in mapping.js (refuted); the real count is 63 across other modules. The double focus ring is not a Fluent pattern. The Excel yellow preset fails contrast on screen.
- **Units:** UN/ECE PK/CT/BX/CS have status "X" (deleted), not deprecated.
- **JSON validation:** Pydantic strict whole-model validation breaks ISO dates.
- **WinSW:** v2 uses `<domain>/<user>` and `<delayedAutoStart/>`.
- **SQLite:** the app does not use WAL today; `foreign_keys` and a 20 s timeout are already set.
- **Python:** the html.parser fix is in 3.13.6. Gating XML formats on Expat ≥2.7.2 needs ≥3.13.8 on python.org Windows builds.
- **ASVS levels:** 6.3.8, 5.3.3 and 16.5.4 are Level 3 (adopted anyway).
- **Body limit:** Starlette ≥1.6 has RequestBodyLimitMiddleware.
- **Defaults:** react-spreadsheet-import `autoMapSelectValues` defaults to false and `allowInvalidSubmit` to true. The relative delta in Valentine's `select_both_multiple` defaults to 0.01 (Coma 0.15).

## 4. Will not adopt

**Scope**
- PDF, OCR, CAD and any document-image pipeline: out of scope.
- Cloud AI APIs (OpenAI, Azure, Bedrock and so on), Oracle Select AI and Magneto's default cloud reranker: these break the offline, no-cloud rule.
- LLM-generated SQL in any form (Vanna 2.0, Select AI, CHESS candidate-generator and unit-tester agents, DIN-SQL generation code): unsafe on a 17 GB ERP schema (Spider 2.0: 21.3%). DIN-SQL's MIT licence is not the reason.

**Licence**
- pyxlsb (LGPLv3+, unmaintained since 2022).
- odfpy (GPL/LGPL/Apache tri-licence; also slow).
- Jellyfish-7B/8B (CC BY-NC-4.0, plus the Llama 3 Community License).
- elkjs (EPL-2.0 OR GPL-3.0).
- Handsontable (proprietary for commercial use).
- Soda Core v4 (Elastic License 2.0, not OSI; also no Oracle connector and an OpenTelemetry exporter).
- Code from ERPNext and apparelo (GPL-3.0) and from Odoo (LGPL-3): design reference only.
- Code from Pytheas, DataMosaic, thedrna and Auto-Tables (no licence file): ideas only.
- WiX v6/v7: the OSMF fee applies to users with ≥US$10k gross revenue.

**Weight or runtime footprint**
- Valentine at runtime (PuLP, POT, scipy, NLTK; Cupid needs NLTK data). Dev benchmark only.
- Unstructured (huge; requires-python <3.14).
- sentence-transformers, torch and embedding retrievers.
- Great Expectations (≈18 heavy distinct dependencies).
- Pandera (needs pandas or polars).
- frictionless-py and datacontract-cli at runtime (21 dependencies; CI only).
- pandas, including `read_html` and `read_excel`.
- CleverCSV as a dependency (3 extra packages; the idea is reimplemented).
- ssf (stale, 7 dependencies; a narrow renderer is used instead).
- scipy just for Hungarian assignment.
- networkx.
- Apache Hop, Talend Open Studio (retired) and Pentaho as runtimes.
- WrenAI runtime (Rust/DataFusion; possible future AGPL modules).
- LibreOffice headless in v1 (large install, extra attack surface).
- `uvicorn[standard]` extras.
- httpx and test tools in the runtime.

**Unmaintained or broken**
- ezodf (2015).
- FlexMatcher (uses `.ix`/`.as_matrix`, removed in pandas 1.0; pins python-Levenshtein 0.12.0 with no cp313 Windows wheel).
- NSSM (2014/2017).
- passlib (last release 2020).
- starlette-csrf (2023, naive double-submit).
- react-csv-importer (2023).
- python-oracledb 26.0.0/26.0.1 until 26.1.0 ships (issue #610 pool hang).

**Design**
- openpyxl `read_only=True` for understanding: no merges or hidden state.
- calamine as the primary .xlsx or .xls reader: drops formats and hidden state, and error cells become ''.
- Fuzzy auto-accept of master values at any score.
- Fuzzy matching of PO or order references.
- Implicit master creation (Frappe `create_missing_link_records`, Odoo on-the-fly variants).
- Per-row commit or "Partial Success" posting.
- `batch_size` combined with autocommit.
- DBMS_LOCK and `ALLOCATE_UNIQUE` (the latter commits) on a single-instance deployment.
- Audit, immutable or blockchain tables in the client's Axpert schema.
- Oracle Text and CTXCAT.
- OFFSET paging.
- EXPLAIN PLAN at runtime inside READ ONLY.
- `conn.dbop`, SQL Monitor or AWR without a Tuning/Diagnostics Pack licence.
- SQLite WAL on bundled SQLite 3.50.4.
- `__Host-` cookies without TLS.
- The `secure` header preset (weaker than the current CSP).
- keyring under a service account.
- In-process pywin32 services.
- PyInstaller one-file (antivirus false positives).
- `role="application"` on the graph.
- Excel's yellow preset as on-screen text (4.12:1).
- React-based libraries (React Flow, react-spreadsheet-import): no React and no CDN under the strict CSP.
- Cytoscape.js (canvas).
- SaaS importers (Flatfile, OneSchema, Dromo, nuvo, CSVBox): cloud only, patterns copied only.
- Oracle Free for the 17 GB rehearsal or for performance numbers (12 GB, 2 GB RAM, 2 threads, unpatched).
- Docker Desktop on POPPYS hardware until its subscription terms are checked against POPPYS's size; alternatives are Oracle Free's native Windows installer and Podman/WSL2.
